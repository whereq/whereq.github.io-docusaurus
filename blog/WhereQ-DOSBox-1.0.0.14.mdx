## You pressed Save twice

You were halfway through a fight with something large. You pressed **Save**.

Nothing came back. The slot did not fill, the spinner did not spin, and the phone was busy for a second — long enough that you pressed **Save** again, because the first press clearly had not registered.

The second press did register. It saved. And that was the problem: the file that went to disk was not necessarily the file that the second press asked for.

That is the whole of 1.0.0.14. It is a patch release with three repairs, all of them in the save-state plumbing, and it changes nothing about the save file itself.

## A late answer used to answer the next question

The app does not drive the emulator core directly. It asks it to do things — save this state, restore that state — and the answer comes back through a channel. A save or a restore has a time limit, because a core that has stopped answering must not hang the phone forever.

When one overran its limit, the request was given up on. But the core did not know that. It finished the work anyway, and handed its result back — into the place where the *next* request was already waiting.

So the next save got the previous save's answer. The app was told that the new save was done. The file on disk was the file the old request wrote.

Every request now carries a generation number. A completion that arrives after its own request gave up is dropped: it belongs to a request that no longer exists.

## Two names for one file

The second repair is older and quieter. A DOS program can duplicate a file handle with INT 21h/45h, and from that moment on the file has two names and one identity.

A restore puts the machine back exactly as it was, so the two names have to come back too, sharing one file the way they shared it before. That is what happens now: the reference count goes back as it was saved.

Before, the count did not survive the trip. Close one of the two names and the other went down with it — the close took the shared file's reference count to zero, and the surviving name became *"invalid handle"*.

## The descriptor that stayed open

The third repair is about the machine a restore replaces. Loading a state throws the running machine away and builds a new one from the file. The old one has to be closed, and closing it has to close the files it holds — the real files on the phone, not the guest's idea of them.

Before, a state in which a handle was shared left one host file descriptor open on every restore. Not a crash, not a wrong answer: a descriptor that stayed open for the rest of the session, one per restore, until the app was closed.

Now the discarded machine is closed properly, whatever its reference count.

## Your save states still load

**The save-state format did not change.** All three fixes are in the snapshot's plumbing, not in the file, so every save state written by the earlier releases loads normally.

That is worth saying out loud, because it is the part readers actually care about: a release that quietly re-cut the state format would leave a shelf of unopenable slots behind it.

## The other end of the same line

The **Resume** button restores the newest slot of the last game you played, and it tells you what it is about to do — *Resume whereq-demo-bundle · slot 1 · just now*.

A save that answers for the wrong request is exactly the kind of thing nobody notices there, and exactly the kind of thing that costs you an evening.

## The documentation grew too

The same release brought two documents into the repository: an **interrupt map** — every INT in the emulator, what it is for, and which code answers it — and a **user guide** that walks through the app with the screenshots it uses. The repository's documentation grew a great deal.

The guide is worth having if the app is new to you. The interrupt map is worth having if you are the kind of person who wants to know what the emulator does with `INT 21h`.

## Thank you, DOSBox

None of this is possible without the DOSBox project.

**DOSBox** was written by the [DOSBox Team](https://www.dosbox.com/crew.php) — a volunteer crew who took an operating system from 1994 and made it runnable on every machine the world has produced since, including the ones that did not exist yet. They kept it alive for three decades and gave it away to anyone who wanted it. WhereQ-DOSBox is a thin layer on top of their work. The originality, the craft and the generosity are entirely theirs.

This port is built on **[Em-DOSBox](https://github.com/dreamlayers/em-dosbox)**, the Emscripten build of DOSBox r4305 by [Boris Gjenero](https://github.com/dreamlayers), which grew out of [Ismail Khatib's](https://github.com/CeRiAl) first attempt to compile DOSBox with Emscripten, and rode on the Emscripten work of [Alon Zakai](https://github.com/kripken/). The SDL2 library by [Sam Lantinga](https://github.com/libsdl-org/SDL) carries the window, the audio and the touch input.
