## 浏览器里的那个 DOS，不算数

把 DOS 弄到手机上，最快的办法是打开一个网页：页面加载一份 JavaScript 版的 DOSBox，屏幕上就出现了 `C:\>` 提示符。它能用。但它和 DOSBox 本来就不是同一种东西。

一个跑在浏览器标签页里的 WebAssembly x86 模拟器，得做三件原生程序从不需要做的事：它得住在一个网页里，它的每一个像素、每一段声音都得向浏览器去要，它还得在浏览器定的规矩下活着。画面是一块 canvas，声音是一个要人喂着的音频缓冲区，键盘是网页自己的问题。最要命的是，你没法把这台机器写下来再读回去——因为它本来就不是机器，是一个标签页。

我想要的是另一样东西：DOSBox 核心本身，原生编译，作为库跑在 App 里面。**1.0.0.7** 就是让这件事从一个计划变成一个 APK 的那个版本。

## 「装进 APK」到底是什么意思

具体来说：APK 里为三种 ABI 各带一个原生库——`libdosbox.so`——而这个库**就是**模拟器。不是套了个壳，也不是去连什么服务器：CPU 核心、DOS 内核、硬件模拟、外壳命令，以及 SDL2 后端，全都在里面。SDL2 是静态链接进去的，所以每个 ABI 只带一个原生库，运行时也就不再依赖 SDL2。

三个 ABI 是 `arm64-v8a`（64 位手机）、`armeabi-v7a`（32 位手机）和 `x86_64`——最后这个根本不是手机的 ABI，它在这儿是因为 SDK 提供 x86_64 的系统镜像，验证用的测试机架跑在模拟器上。构建用 CMake 加 NDK，SDL2 固定在 2.30.0。外层的 App 层是 Kotlin 和 AndroidX，通过 JNI 跟模拟器打交道：一个函数负责加载 `libdosbox.so`，另一个把 SDL 的画面交出来，键盘则走和真键盘完全一样的路径——`SDL_PushEvent` → mapper → `KEYBOARD_AddKey`。游戏那边不需要学第二套输入方式。

| | |
|---|---|
| 模拟器核心 | DOSBox r4305（SDL2 分支），从 Em-DOSBox 引入 |
| 原生库 | `libdosbox.so`，每个 ABI 一个，SDL2 静态链接 |
| ABI | `arm64-v8a`、`armeabi-v7a`、`x86_64`；minSdk 21，即 Android 5.0 及以上 |
| 构建 | NDK r27 + CMake，SDL2 2.30.0 静态 PIC 归档 |
| 默认核心 | `core=auto`——实模式走解释器，保护模式走重编译核心 |
| APK | 约 15.5 MB，原生库不压缩存放 |

## 真正难的那一块：JIT

DOSBox 自带一个 JIT——重编译核心：不逐条解释指令，而是在程序运行的时候把一段 x86 翻译成机器码。上游编译它的 x86 dynrec 靠 GCC 插件，NDK 的 clang 做不到；而 Android 也不允许另一半做法：原版的代码缓存是先 `malloc` 一块，再 `mprotect(PROT_EXEC)` 把它变成可执行的，而加固过的设备会拒绝让堆内存变成可执行。

两件事最后都有解。可移植的代码生成器——arm64、armv7、x86_64——不需要插件，直接往缓冲区里生成机器码；而在 Android 上，代码缓存从一开始就以匿名的 RWX 内存申请，这是普通非受信应用唯一被允许做的那种 JIT 式分配，`mprotect` 那段代码则在 Android 上直接编译掉了，因为那块内存本来就是可执行的。这就是为什么 JIT 被编进了三个 Android ABI 的 `libdosbox.so`。

随包发布的配置是 `core=auto`：一直待在实模式的程序跑解释器，跟以前一模一样，JIT 根本不会启动；一旦切换到保护模式的程序，就在第一次模式切换时交给重编译核心。这个改动是在 **1.0.0.6** 落地的，两条路径当时都在模拟器上验证过——STARFALL 走实模式，Ultima VIII 走保护模式。

## 1.0.0.7 带来的：可以在 App 里选核心

1.0.0.6 里，我在文档里、在这个仓库里写过一句：*如果 JIT 的代码缓存分配不出来，就把 `core=normal` 写进 `dosbox.conf` 作为退路。*

然后我照着自己这句话试了一遍——它行不通。`dosbox.conf` 每次启动都会从随包的模板重新生成，这是故意的，好让模板一改、已经装在手机上的版本也能拿到；这意味着手工改过的文件下次启动就被覆盖。何况那个文件本来就在 App 的私有目录里，任何文件管理器都够不着。**我写进文档的那条退路，其实根本够不着。** 确实有那么一小撮老 DOS 程序在重编译核心上会出毛病，而我当时没给它们留任何出路。

所以 1.0.0.7 把这个选择搬进了 App。Files 面板上的 **Config** 按钮弹出一个对话框，列着 DOSBox 认识的所有核心：

`auto` 是默认，`normal` 是代码缓存分配不出来时的退路，而 `dynamic`、`simple`、`prefetch` 本来就是 DOSBox 一贯有的选项，从来没有理由藏起来。这个选择会被存下来、写进生成出来的配置文件，重启之后还在，App 升级之后也还在。一个小对话框，换来一句终于能兑现的承诺。

## 两句实话

**关于体积。** 第一篇公告里说 APK 大约 5.3 MB。现在大约 15.5 MB——与其让你下载时才发现，不如我先说清楚。两个原因，都是故意的：原生库在 APK 里**不压缩**存放，Android 可以直接从 APK 里映射它们，不必每次安装都复制到磁盘；App 层换成 Kotlin + AndroidX，又带来了大约 4.5 MB 的 dex。这笔交换是：下载大一点，换安装快一点。

**关于验证。** 我跑过的东西，全都跑在**模拟器**上——API 37，x86_64。真机 ARM64 还没跑过，也没有真机上的性能数字。桌面基线用同一套核心、同一组特性构建，在 x86_64 主机上测到解释器大约每秒 1.27 亿条指令；实时节奏的检查也显示，模拟器只用掉不到一个核心的 5% 就能以 1× 跑 DOS。但手机上的那个数字仍然缺着，而 JIT 那块 RWX 代码缓存，正是我最先想在真机上量一量的风险面。
