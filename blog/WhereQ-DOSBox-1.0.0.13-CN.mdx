## 「刚刚」

午饭之后你回来接着打。点那个写着「五小时前」的档位。游戏原样回来了——那只大家伙、血条、你当时站着的那个房间，都在你离开时的样子。

然后档位上写着的是「**刚刚**」。

存档还是你存的那一份，游戏还是你走时的那一刻。只有时间在说谎，而且它撒的方向刚好是让这个应用显得不可信：它唯一该记住的事，它自己没记住。

1.0.0.13 的全部内容就是这个。这是我发过的最小的一版，修复也只有三行。

## 先说前提：存档已经搬到应用外面了

这个 bug 得先说清楚存档放在哪儿才讲得通，因为 1.0.0.12 把它们搬走了，而那一版在这里一直没发过文章。简单交代一下。

在那之前，存档是应用私有目录里的一个文件。卸载应用——或者手机丢了、换手机了——所有存档跟着一起没。现在应用可以自己留一份在你手上的地方：在手机上选一个文件夹（**Config → Saves folder**，或者第一次存档之后弹出来的那个邀请），之后每个档位都会镜像到那里，压成 gzip，就放在游戏旁边。

```
  应用                              你选的那个文件夹
  ──────                          ────────────────────
  存档   ── gzip ──▶                STARFALL/
                                    slot1.gz
                                    slot2.gz
                                    bundle.zip      (游戏本身)
```

于是重装、换手机、或者手滑删了应用，东西都能回来：游戏按名字 offer 给你恢复，它们的存档已经在那里了。同名的两个压缩包会按名字区分——*game* 和 *game (2)*——所以它们的存档不会混到同一个地方。

## 错在哪一行

本地那份档位不见了的时候——重装了、换手机了——应用会从镜像里把它重建出来。文件是新写出来的，于是带上了写的那一刻的时间戳。

启动器读的就是这个文件上的时间。于是五小时前存的档位，从镜像里恢复出来，就成了「刚刚」。

快照本身一点问题都没有，而且从来就没问题过：机器、声音芯片、DOS 文件句柄，全都原样回来了。错的只有那个标签。可这反而更糟，因为一个错的标签会让你开始怀疑底下的东西——你会怀疑这次恢复到底忠实不忠实，其实恢复完美无缺，撒谎的是日期。

修法是把时间跟着一块带过去。镜像知道这个档位究竟是什么时候存的，重建出来的本地文件现在拿到的就是这个时间，而不是当前时间：

```kotlin
// Keep the original SAVE time: restoring rewrites the local file, so
// without this the slot would show "just now" after every load.
if (ok) doc.lastModified().takeIf { it > 0L }?.let { local.setLastModified(it) }
```

一行活儿，一行代码，档位于是又变回「5 小时前」。

## 手机上的名字

启动器名字、通知和桌面图标现在都带着这个项目自己的名字和标记：**WhereQ-DOSBox**。

包名是 `com.whereq.dosbox`，下载文件名是 `whereq-dosbox-1.0.0.13.apk`，所以这一版可以直接覆盖安装上一版——包名一样、签名密钥一样，不用先卸载。你的游戏和存档原地不动。

## 你的存档还是读得出来

**存档格式什么都没改。** 修的是启动器，不是快照，所以之前各版本写下的存档都照常读得出来——文件布局仍然是版本 10，和当初把鼠标块精简成稳定配置之后那一版一样。

这比听起来更重要：一次悄悄改掉格式的发布，会留下一批再也打不开的存档。老实做法是——格式真变了就大声改，带版本号地改。
