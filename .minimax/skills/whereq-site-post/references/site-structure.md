# Site structure — whereq.github.io-docusaurus

Everything below was read from the repo itself. Re-verify against the repo if
it has changed; this file is a map, not the law.

## Layout

| Path | What it is |
|---|---|
| `blog/*.md`, `blog/*.mdx` | ~200 blog posts, flat, one file each |
| `blog/authors.yml` | The author registry — currently one entry, `whereq` |
| `blog/tags.yml` | Vestigial Docusaurus sample tags. Tags are **not** centrally registered |
| `docs/` | Minimal; one `intro.md`, autogenerated sidebar |
| `src/pages/` | `index.tsx`, `about.tsx`, `news.tsx`, `articles.md`, `markdown-page.mdx` |
| `src/data/news.ts` | The News page's data — apps and their announcements |
| `src/data/news-release-ledger.ts` | Release history per app. Not imported by the page |
| `src/theme/` | Swizzled components (Giscus comments on blog post pages) |
| `src/css/custom.css` | Global styles |
| `static/img/` | Site images, served at `/img/...` |
| `static/img/apps/` | One logo per application, for the News page tiles |
| `bin/whereq.sh` | Lifecycle wrapper: `dev`, `build`, `serve`, `push`, `deploy`, `all`, `clean` |

## Locales — the important subtlety

`docusaurus.config.ts` declares `i18n.locales: ['en', 'zh-CN']` with
`defaultLocale: 'en'`. But **there is no `i18n/` directory in the repo**, so
Docusaurus has no per-locale translation folders of your own. What that means
in practice:

- The **chrome** is Chinese in the zh-CN build — navbar, search box, "Skip to
  main content" — because Docusaurus ships its own built-in `zh-CN`
  translations.
- The **content** is not translated. Posts and pages render the English
  originals in both locales.

The established convention for a Chinese post is therefore **a separate blog
file with a `-CN` suffix**, not a Docusaurus translation:

```
blog/Hermes-Agent-vs-OpenClaw-Full-Comparison.mdx
blog/Hermes-Agent-vs-OpenClaw-Full-Comparison-CN.mdx
```

Both files appear in both locale builds. A Chinese post therefore has to read
as a standalone article for a reader who never sees the English one.

## Frontmatter

```yaml
---
title: "Quoted human title"
slug: Filename-Stem
date: 2026-11-12
tags: [inline, kebab, array]
authors: whereq
---
```

- `slug` equals the filename stem in 203 of the 204 existing posts. The one
  exception is `WhereQ-Universe-Architecture`, whose slug is lowercase — so
  match the stem, don't lowercase it.
- `authors` must be a key in `blog/authors.yml` — currently `whereq`
  ("Dazhi Zhang (Tony)", `/about`). `onInlineAuthors` is `warn`, so an
  unknown author only warns.
- `date` is `YYYY-MM-DD`.
- `tags` are inline and unregistered. `onInlineTags` is `warn`, and a full
  build emits ~400 such warnings for pre-existing posts, so they are noise.

## Blog URLs

A post's URL is `/blog/<slug>/`. The blog index shows `postsPerPage: 10`,
with `blogSidebarTitle: 'Recent Posts'` and a sidebar count of 20.

`<!-- truncate -->` marks where the index-page excerpt ends. Place it after
the opening paragraphs so the list view shows a clean teaser.

## Images

- `static/img/**` is served at the site root — `static/img/apps/foo.png` →
  `/img/apps/foo.png`.
- In a post, reference images by absolute path: `<img src="/img/apps/foo.png">`.
- `onBrokenMarkdownImages` is `ignore` and `onBrokenLinks` is `warn`, so
  **a wrong image path does not fail the build and barely shows up in it.**
  Verify by grepping the built HTML.
- The site theme is dark-first (`#0d1117` background, amber `#f5a623`
  accent) with a manual color-mode switch. `respectPrefersColorScheme` is
  **off**, so a `<picture>`/`prefers-color-scheme` pair would track the OS,
  not the site's own toggle. Use `ThemedImage` instead:

  ```mdx
  import ThemedImage from '@theme/ThemedImage';

  <ThemedImage
    alt="WhereQ-DOSBox"
    sources={{
      light: '/img/apps/whereq-dosbox-logo.png',
      dark: '/img/apps/whereq-dosbox-logo-transparent.png',
    }}
    width="300"
  />
  ```

  That requires `.mdx`. `markdown.format` is `detect`, so plain `.md` is
  CommonMark unless it contains MDX syntax.

## The News page

`src/pages/news.tsx` renders `src/data/news.ts`. Two sections:

- `OPEN_SOURCE_APPS` — every app has a public repo, so it gets a **Source**
  button (built from `repo`).
- `PROPRIETARY_APPS` — no `repo`, so no Source button. An open-source app
  listed here is a bug.

`AppCategory` shape:

```ts
{
  id: 'whereq-dosbox',      // anchor id + search key
  name: 'whereq-dosbox',
  tagline: 'One line about the app.',
  url?: 'https://...',       // omit when the app has no hosted instance
  repo?: 'whereq-dosbox',    // open-source apps only
  logo: '/img/apps/whereq-dosbox.png',
  accent: '#14243d',
  announcements: [ /* {title, url, date}, newest first */ ],
}
```

`announcements` entries: `title` (headline), `url` (site-relative
`/blog/<slug>` or an absolute external URL), `date` (`YYYY-MM-DD`). The page
sorts newest-first itself via `byNewest`, so do not pre-sort.

The page's logo tiles put a light plate (`#f1f3f5`) behind each logo so a
dark brand mark reads on the dark theme and a light one reads in light mode.

## The release ledger

`src/data/news-release-ledger.ts` holds `RELEASE_LEDGER: Record<string,
LedgerEntry[]>` keyed by the same app `id`. `LedgerEntry` is
`{version, date, title, url?}`. It is **not** imported by the News page, so
it stays out of the browser bundle.

Helpers already defined in that file — use them instead of hand-written URLs:

```ts
const tag = (repo, version) => `${GH}/${repo}/commits/${version}`;
const doc = (repo, path, ref = 'main') => `${GH}/${repo}/blob/${ref}/${path}`;
```

The ledger's header comment lists where each app's release notes live.

## Build, verify, deploy

```sh
./bin/whereq.sh dev       # dev server, hot reload, :3000
./bin/whereq.sh build     # production build into ./build/
./bin/whereq.sh serve     # preview ./build/
./bin/whereq.sh push "m"  # commit + push source to origin/main
./bin/whereq.sh deploy    # push ./build/ to the Pages repo
./bin/whereq.sh all       # build → push source → deploy
```

A full build takes 10–15 minutes — run it in the background with a timeout of
at least 2400 seconds. The mechanics of the release are in
`references/release-flow.md`.

`npm run typecheck` (`tsc`) is the only verification step configured, and it
has **pre-existing** errors unrelated to content work: a missing `locale`
argument in `docusaurus.config.ts`, and a `JSX` namespace in four files.
Compare against a clean tree before assuming a content change caused them.

There is no test suite and no linter.

## Deployment model

The built site is pushed to a **separate Pages repo** (`whereq.github.io`,
`master` branch), not to a `gh-pages` branch here. The remote for the source
repo is `git@whereq.github.com:whereq/whereq.github.io-docusaurus.git` —
note the `whereq.github.com` SSH host alias, not plain `github.com`.

## House style

- MetroUI radius **xs is 2px** — the whereq family standard. A pill-shaped
  button is a second button; do not use `border-radius: 999px`.
- Giscus comments are injected on full blog-post pages via a swizzled
  `src/theme/BlogPostItem/index.tsx`.
- Search is offline/local via `@easyops-cn/docusaurus-search-local`, indexing
  blog, docs and pages in both `en` and `zh`.
- The site's own `CLAUDE.md` is the authoritative in-repo guide — read it
  before a large content change.
