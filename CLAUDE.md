# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

WhereQ, a personal engineering blog (https://whereq.github.io) built with Docusaurus 3.10 + React 19 + TypeScript. Content is ~200 blog posts migrated from a previous Hexo site. The blog is the primary surface; `docs/` is minimal.

This is the **docs hub**, published from the `whereq/whereq.github.io` Pages repo. It is NOT `whereq.com` — the apex domain is the WhereQ map app, a different product in the Universe. `www.whereq.com/docs/...` answers HTTP 200 with that app's shell, not with these docs, so the canonical URL in `docusaurus.config.ts` must name `whereq.github.io`.

## Commands

Use the `bin/whereq.sh` lifecycle wrapper for anything beyond dev:

```bash
./bin/whereq.sh dev       # dev server, hot reload — http://localhost:3000
./bin/whereq.sh build     # production build into ./build/
./bin/whereq.sh serve     # preview ./build/ locally
./bin/whereq.sh clean     # wipe .docusaurus/ and build/
./bin/whereq.sh push "msg" # commit + push source to origin/main
./bin/whereq.sh deploy    # build (if needed) + push ./build/ to the Pages repo
./bin/whereq.sh all       # build → push source → deploy Pages (the release flow)
```

Underlying npm scripts also work: `npm run start`, `npm run build`, `npm run serve`, `npm run typecheck` (runs `tsc`). There is no test suite or linter configured — `npm run typecheck` is the only verification step.

## Deployment model (two repos)

This is a **source repo** (`whereq.github.io-docusaurus`). The built static site is pushed to a **separate Pages repo** (`whereq.github.io`, `master` branch) — NOT to a `gh-pages` branch here. `whereq.sh deploy` clones the Pages repo into a temp dir, replaces its contents with `./build/`, and pushes. Both operations use the `github.com-whereq` SSH host alias (configured in `~/.ssh/config`). The README's `yarn deploy` instructions are Docusaurus defaults and are NOT the deploy path used here — use `whereq.sh` instead.

## Content conventions

- **Blog posts** live as flat files in `blog/*.md` (or `.mdx`). Frontmatter uses: `title`, `slug`, `date`, `tags` (inline array), `authors: whereq`. Authors are defined in `blog/authors.yml`.
- Tags are declared inline in posts and are not centrally registered; `onInlineTags`/`onInlineAuthors` are set to `warn`, so unknown tags/authors build fine with warnings.
- **Docs** live in `docs/` with an autogenerated sidebar (`sidebars.ts`).
- **Custom pages** are in `src/pages/` (`index.tsx` homepage, `about.tsx`, `articles.md`, `news.tsx`).
- **The News page** (`src/pages/news.tsx`) is the WhereQ Universe announcement hub. It has two sections: **Open Source Applications** (each with an *Open app* and a *Source* button) and **Proprietary Applications** (*Open app* only — their repositories are private, so there is no Source link). Under each app is a two-column table of **announcements** (article | published date), newest first. An announcement is a curated article written in this project, not a release tag — see `src/data/news.ts` for the shape and the flow for adding one.
- **Release history** behind the announcements lives in `src/data/news-release-ledger.ts`, which the page does **not** import (it stays out of the browser bundle). Each entry is the application's own release note, read from that application's repository — the version, date and wording are the application's own. To refresh it, re-read the app's changelog / release-notes docs and git tags and update the ledger.
- **Logos** for the News page live in `static/img/apps/`, one per application, each on a light plate so dark and light brand marks both read.
- **MetroUI**: radius **xs is 2px** — the whereq family standard (chips, tags, scrollbars and buttons all use it). A pill-shaped button is a second button; do not use `border-radius: 999px`.
- **The announcement skill** is `.minimax/skills/whereq-site-post/` (installed copy at `~/.minimax/skills/whereq-site-post/`). It covers the whole flow: author the EN + CN post pair, register `{title, url, date}` in the app's `announcements` array, then release with `./bin/whereq.sh all`. The release mechanics live in its `references/release-flow.md`.

## The WhereQ Atlas

`/atlas/` is a **wiki**, and it is deliberately wider than the WhereQ Universe. It holds four collections, and a page in one has no obligation to know about the others:

| Collection | Route | What it holds |
|---|---|---|
| **Universe** | `/atlas/universe/` | The 13 applications, one page each |
| **References** | `/atlas/resources/` | The standards and tools the work is built on, each written to stand alone |
| **DOS Games** | `/atlas/dos-games/` | The DOS games that run on WhereQ-DOSBox — the bundle to download, the setup, how to play, the licence notice and a comment thread |
| **Glossary** | `/atlas/glossary/` | The vocabulary, defined once, with its own page shape |

Architecture:

- **Content** lives in `src/data/atlas*.ts`. `atlas-types.ts` holds the shared types; `atlas-universe.ts`, `atlas-resources.ts`, `atlas-dos-games.ts` and `atlas-glossary.ts` hold the content; `atlas.ts` is the barrel that assembles the collections, the questions and the threads. A new collection is a new module plus a line in the barrel — the layout does not change.
- **Layout** lives in `src/components/Atlas/`. `AtlasShell` draws the two-level tree (collection → group → page) and the "On this page" rail; `AtlasEntryPage` serves *every* page whether it is an application or a reference; `AtlasCollectionPage` serves *every* collection; `AtlasHomePage` and `AtlasGlossaryPage` are the two special shapes.
- **Routes** are `src/pages/atlas/<collection>/<entry>.tsx`. Docusaurus has no dynamic route segments, so each page is a thin file that names its collection and entry id.
- The flat URLs the Atlas used to have (`/atlas/<app>/`) redirect to `/atlas/universe/<app>/` through `@docusaurus/plugin-client-redirects`. Add a redirect there when a page moves.
- Pages link to each other with `related` — the wiki's "See also". `ATLAS_THREADS` are the paths that cross between collections; they are the reason the Atlas is one wiki rather than four lists.
- **Reference pages must state their source.** Version numbers and dates are checked against the project's own documentation, and a claim that cannot be traced to a primary source is not made. The "Where to read more" block links to that source.
- Application ids match `src/data/news.ts` wherever the app appears there, so the two cannot drift.
- **A DOS game page carries four things the other pages do not**: the `facts` rows (author, publisher, published, platform, genre, entry point, bundle), the `notice` band (the licence — study and communication only, taken down on request), the download link to `/downloads/dos-games/<slug>.zip`, and the `comments` thread the collection switches on. The bundles are copied unchanged from `~/git/dos/games/`; the SHA-256 on the page is the upstream one, so a copy can be checked.
- **The setup on a game page is tested, not remembered.** The launch script a game needs (`REKO3` for 三国志英杰传, the default `MK` for 真人快打), the keys that start it (`F1` for 真人快打) and the screens behind them were all read off an emulator running WhereQ-DOSBox. If a step is not known to work, it does not go on the page.
- **The nav panel's scrollbar is `@whereq/react`'s**, not a hand-rolled one. `AtlasShell` uses the library's `Scrollbar` component — it carries the class, the `--wq-sb-*` variables and the stylesheet — and renders the library's `scrollbarCss` in the page under the library's own style id (so the component finds it and injects no second copy). That puts the scrollbar in the server HTML, so there is no flash. The `<nav>` stays the sticky grid item (`.railNav`); the `Scrollbar` inside it is the scroll container (`.rail`). The site-wide amber scrollbar in `custom.css` skips any `.wq-scrollbar` element so the two do not fight.

## Architecture notes

- **Config is async** (`docusaurus.config.ts` exports `createConfig()` as a promise) specifically so `remark-math` and `rehype-katex` can be dynamically imported. Math rendering (KaTeX) is wired into docs, blog, AND pages via `remarkPlugins`/`rehypePlugins`. The KaTeX CSS is loaded from a CDN `<link>` in `stylesheets`.
- **Giscus comments** are injected by swizzling `src/theme/BlogPostItem/index.tsx`, which wraps the original component and renders `src/components/GiscusComments` only on full blog-post pages (`isBlogPostPage`). An Atlas collection can switch the same component on for its own pages with `comments: true` on the collection — the DOS Games shelf does, so every game page carries a thread. Repo/category IDs are hardcoded in `src/components/GiscusComments` and point at the `whereq/whereq.github.io` GitHub Discussions.
- **Search** is client-side/offline via `@easyops-cn/docusaurus-search-local` (indexes blog, docs, and pages in both `en` and `zh`) — there is no Algolia.
- **i18n**: `en` (default) + `zh-CN`.
- **Theme**: dark-first (dark navy `#0d1117` bg, amber `#f5a623` accent). Color mode switch is enabled but `respectPrefersColorScheme` is off. Global styles in `src/css/custom.css`.

## Gotchas

- `showLastUpdateTime`/`showLastUpdateAuthor` are disabled in config.
- `onBrokenLinks` and `onBrokenMarkdownLinks` are `warn`, not `error` — broken links won't fail the build.
- `.claude/` is gitignored (local-only memory/settings).
