# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

WhereQ, a personal engineering blog (https://www.whereq.com) built with Docusaurus 3.10 + React 19 + TypeScript. Content is ~200 blog posts migrated from a previous Hexo site. The blog is the primary surface; `docs/` is minimal.

## Commands

Use the `bin/whereq.sh` lifecycle wrapper for anything beyond dev:

```bash
./bin/whereq.sh dev       # dev server, hot reload — http://localhost:3000
./bin/whereq.sh build     # production build into ./build/
./bin/whereq.sh serve     # preview ./build/ locally
./bin/whereq.sh clean     # wipe .docusaurus/ and build/
./bin/whereq.sh push "msg" # commit + push source to origin/main
./bin/whereq.sh deploy    # build (if needed) + push ./build/ to the Pages repo
./bin/whereq.sh all       # build → push source → deploy Pages (the release flow)
```

Underlying npm scripts also work: `npm run start`, `npm run build`, `npm run serve`, `npm run typecheck` (runs `tsc`). There is no test suite or linter configured — `npm run typecheck` is the only verification step.

## Deployment model (two repos)

This is a **source repo** (`whereq.github.io-docusaurus`). The built static site is pushed to a **separate Pages repo** (`whereq.github.io`, `master` branch) — NOT to a `gh-pages` branch here. `whereq.sh deploy` clones the Pages repo into a temp dir, replaces its contents with `./build/`, and pushes. Both operations use the `github.com-whereq` SSH host alias (configured in `~/.ssh/config`). The README's `yarn deploy` instructions are Docusaurus defaults and are NOT the deploy path used here — use `whereq.sh` instead.

## Content conventions

- **Blog posts** live as flat files in `blog/*.md` (or `.mdx`). Frontmatter uses: `title`, `slug`, `date`, `tags` (inline array), `authors: whereq`. Authors are defined in `blog/authors.yml`.
- Tags are declared inline in posts and are not centrally registered; `onInlineTags`/`onInlineAuthors` are set to `warn`, so unknown tags/authors build fine with warnings.
- **Docs** live in `docs/` with an autogenerated sidebar (`sidebars.ts`).
- **Custom pages** are in `src/pages/` (`index.tsx` homepage, `about.tsx`, `articles.md`).

## Architecture notes

- **Config is async** (`docusaurus.config.ts` exports `createConfig()` as a promise) specifically so `remark-math` and `rehype-katex` can be dynamically imported. Math rendering (KaTeX) is wired into docs, blog, AND pages via `remarkPlugins`/`rehypePlugins`. The KaTeX CSS is loaded from a CDN `<link>` in `stylesheets`.
- **Giscus comments** are injected by swizzling `src/theme/BlogPostItem/index.tsx`, which wraps the original component and renders `src/components/GiscusComments` only on full blog-post pages (`isBlogPostPage`). Repo/category IDs are hardcoded there and point at the `whereq/whereq.github.io` GitHub Discussions.
- **Search** is client-side/offline via `@easyops-cn/docusaurus-search-local` (indexes blog, docs, and pages in both `en` and `zh`) — there is no Algolia.
- **i18n**: `en` (default) + `zh-CN`.
- **Theme**: dark-first (dark navy `#0d1117` bg, amber `#f5a623` accent). Color mode switch is enabled but `respectPrefersColorScheme` is off. Global styles in `src/css/custom.css`.

## Gotchas

- `showLastUpdateTime`/`showLastUpdateAuthor` are disabled in config.
- `onBrokenLinks` and `onBrokenMarkdownLinks` are `warn`, not `error` — broken links won't fail the build.
- `.claude/` is gitignored (local-only memory/settings).
